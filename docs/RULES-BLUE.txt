STANDING RULES (teacher's):
- Sections exactly as the book: A, B, C... with numbering restarting per section. Never merge sections or renumber. Reviews/tests keep 1-N numbering with direction banners like "[1-2]".
- Every section: book's Korean direction + explicit typing rule in sectionInstructionKo ("빈칸에 들어갈 말만 쓰세요. (문장 전체를 쓰지 마세요.)" / "문장 전체를 쓰세요." / "알맞은 말을 골라 쓰세요."), answerMode choice|words|sentence. Each printed blank box = one blank.
- NEW (Jay 2026-10-10): when an item has TWO OR MORE answers (e.g. circle every noun in "Tom is a student." -> Tom, student), give one blank per answer; all must be filled; ANY ORDER is correct. Data: blanks: N, unordered: true, accept lists with pipe-separated tuples (e.g. "Tom|student"); engine permutes blanks for grading. Never accept just one of two required answers.
- Circle/underline tasks: student types the circled word(s). Underlined words in prompts must be visible (<u>...</u>).
- Multiple-choice options in EXACTLY the book's order and numbering (①-⑤).
- Korean answers: accept several correct forms (synonymous endings, spacing, punctuation; e.g. ~해도 된다 / ~해도 좋다; 명사 / 명사(noun)). English: all valid forms (contractions/full, optional final period, curly apostrophes). Never accept a wrong form. Error-correction items need the corrected form.
- Book examples with printed answers: example:true, displayOnly:true; not graded. Keep Korean glosses (promptKo) printed under items.
- Never reveal correct answers in the UI. Wrong-answer review shows the student's answer + instruction only. Metrics: same pipeline as GreenZap (program=greenzap, source=greenzap), app_name = appName, item_id = practiceId:itemId. Item ids unique within each practice (prefix with practice slug).
- Timers slightly generous (walk ~10, run ~18-20, jump ~22-25, fly ~24-28, review 30, wrap ~8, checkup ~6, tests 30-40).
- Do not commit page images, text or answer keys (public repo).
- BLANK = BOX (Jay 2026-10-21, all 10 books): the student must see exactly as many printed blanks (____) as input boxes, each box at its blank. When the book prints one blank line for a multi-word answer and the section says "한 칸에 한 단어", show one blank segment per word ("Ben ______ ______ ______ the guitar"; blanks = word count). Never put words already printed in the sentence into accept. If splitting would hint the answer or answers differ in length (isn't / is not), keep one box per printed blank with phraseBlanks:true (the app then shows "※ 이 문항은 한 칸에 두 단어 이상을 쓸 수 있어요."; do not put it in noteKo). One word for two blanks: sharedAnswer:true (app shows "※ 두 빈칸에 공통으로 들어갈 한 단어를 한 번만 쓰세요."). Examples: exampleAnswer has one part per blank. Every multi-box item needs an accept tuple with exactly one part per box. Check: node scripts/check-blank-count.js (also in check-all-data.js and the Pages deploy workflow).
